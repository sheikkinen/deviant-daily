# Feature Request: Corpus Content Fingerprint + Genre Classification (Haiku Enrichment)

**Priority:** HIGH
**Type:** Feature
**Status:** Judged — APPROVED WITH REVISIONS (2026-08-25), R-1…R-7 folded
**Effort:** 1 day
**Requested:** 2026-08-25
**Depends on:** none (carved out of FR-886; FR-886 now depends on this)
**First consumer / first event:** the FR-886 deterministic draw router,
at its first eligibility join after merge; second consumer: corpus
analytics/rotation (genre distribution report), at the first enrichment
run.

## Summary

A yamlgraph **map-node graph** fans all 7,392 corpus prompts across
haiku-class calls and commits three additive columns per row:

1. `content.sexual`: `safe | mature`
2. `content.gore`: `safe | mature`
3. `genre`: single-label closed-set image classification (list below)

One shot per prompt, structured output (Pydantic), resumable, ~$8
(haiku-4-5 pricing; original ~$3 estimate assumed retired haiku-3.5
prices — operator raised the ceiling to $10, 2026-08-25).
This FR owns the taxonomy; FR-886's router consumes it (FR-885 is
superseded and is not referenced).

## Value Statement

For the draw router (FR-886): mature-prompt × strict-model collisions
waste paid generations; the join needs per-prompt content rungs to
exist at all. For the daily product: the corpus has no genre signal, so
draw variety and analytics are blind — a genre column enables rotation
policy and distribution reporting without any LLM call at draw time.

## Ideal Result

Every corpus row carries a dated fingerprint: two binary content rungs
and one genre label, produced by a witnessed enrichment run, committed
as additive columns with classifier model id. Re-extraction passes them
through untouched. A one-page distribution report shows the corpus
composition by genre × content.

## Problem

- `prompts/corpus.jsonl` (7,392 rows) has no content-class or genre
  fields: `prompt, source_file, local_model, dialect, seed, size,
  created` only.
- FR-886 bundled enrichment with the router and draw integration,
  coupling a ~$3 batch job to a blocked FR; the enrichment has
  independent value (analytics, rotation) and no dependency on the
  tolerance-matrix revision that blocks FR-886.

## Proposed Genre Taxonomy

Grounded in a 2026-08-25 corpus keyword scan (n=7,392) and a 40-prompt
random-sample read (`read_raw_output_first`). **Evidence artifact
(R-1):** `feature-requests/FR-890-evidence.md`, generated by
`scripts/fr890_evidence.py` — exact scan patterns and counts, seed-42
sample row ids, per-sample human genre/sexual/gore labels with an
observed-detail quote each. Sample outcome: all 40 prompts fit a
concrete class (`other`: 0/40); sexual=mature 17/40, gore=mature 3/40.

Single label, dominant
theme; overlaps resolved by the precedence order below (first match on
tie wins):

| # | Class | Corpus evidence (keyword scan) |
|---|-------|-------------------------------|
| 1 | `fetish` | bondage/rope/submissive/spanking — 16% |
| 2 | `gothic` | vampire/demon/satanic/succubus — 21%; gore/decay terms 9% |
| 3 | `furry` | fox girl/wolf_girl/satyr/anthro — 8% |
| 4 | `scifi` | android/cyborg/biomechanical/neon — 10% |
| 5 | `mythological` | goddess/Kali/Venus/valkyrie — 7% |
| 6 | `fantasy` | sorceress/knight/angel/medieval — 17% |
| 7 | `pinup` | pin-up/boudoir/lingerie/vintage glamour — 10% |
| 8 | `fanart` | recognizable IP/celebrity likeness (Marvel, Disney, named persons) — ~1%, kept despite size because it is policy-relevant for image models |
| 9 | `surreal` | dreamlike/floating/Beksiński-style abstraction |
| 10 | `portrait` | photographic/photoreal portrait without genre framing — photo terms 6% |
| 11 | `other` | junk-drawer cap, see constraint C-6 |

Precedence rationale: fetish and IP signals are routing/policy-relevant
and must not be absorbed by broader genre framing; `fantasy` is last
among the themed classes because it is the widest net.

### Taxonomy artifact (R-2)

The runtime single source of truth is
`data/corpus_fingerprint_taxonomy.yaml` (version field `taxonomy: v1`),
containing: the closed genre enum, the precedence order above,
per-label inclusion/exclusion rules, and at least one fixture example
prompt per label (drawn from the evidence sample). FR-886 imports this
artifact — the table above is documentation, not the contract. The
classifier prompt instructs "choose the most specific non-`other`
label"; `other` is demote-last at the boundary, permitted only when no
concrete label's inclusion rules match.

### Content fingerprint semantics (R-3)

Classification is over **prompt text only** — no image, no metadata.
Independent of DeviantArt's image-maturity enum (`tools/gate.py`
consumes image-derived values; these are prompt-derived and share no
code path).

- `content.sexual = mature` iff the prompt requests nudity, explicit
  anatomy, sexual acts, or explicit-erotica directives (booru
  `rating_explicit`, "erotica", "nude", explicit anatomy terms).
  **Nudity is subsumed by `sexual`** — there is no separate nudity
  axis. Suggestive-but-clothed (curves, lingerie-as-costume, cleavage)
  is `safe`.
- `content.gore = mature` iff the prompt requests graphic violence,
  blood, wounds, dismemberment, or body horror as depicted content.
  Aesthetic decay (gothic atmosphere, skeletal architecture) is `safe`.
- Language, ideology, and non-visual themes are intentionally out of
  scope for both axes.
- Fixture tests pin these rules: each taxonomy fixture example carries
  expected `sexual`/`gore` rungs (semantic assertions beyond shape).

### Row schema and failure representation (R-4)

A **classified** row gains exactly two keys:

```json
"content": {"sexual": "safe|mature", "gore": "safe|mature"},
"fingerprint": {"genre": "<enum>", "date": "YYYY-MM-DD",
                "model": "<classifier model id>", "taxonomy": "v1"}
```

An **unfingerprinted** row (classifier failure or out-of-set output)
gains **no keys** — absence of `content` is the marker FR-886 routes
as maximally mature. Failure reasons are counted in the run record
(per-reason counts), not stored per row. `content` is never null and
never partial; a row is atomically classified or untouched.

## Proposed Solution

- **Graph:** `graphs/corpus_fingerprint.yaml` + prompt template — map
  node fans prompts to haiku; per prompt one structured call returning
  `{sexual: safe|mature, gore: safe|mature, genre: <enum>}`. No
  retries; a failed row is recorded as unfingerprinted, not guessed.
- **Enrichment script:** `scripts/enrich_corpus.py` owns writing the
  row-schema keys above back into `prompts/corpus.jsonl` atomically
  (temp file + rename, matching `extract_corpus.py` precedent);
  deterministic batching over row ids; resumable checkpoint keyed by
  row id (`tools.corpus.row_id()` fallback for `unknown` source ids);
  skips rows already classified with the same taxonomy version and
  classifier model id.
- **Cost controls (R-6):** preflight dry-run prints estimated call
  count × per-call price for the selected model id and the projected
  total; a hard stop aborts before the $10 ceiling based on attempted
  calls (tested with a mock counter).
- **Extractor pass-through (R-5):** `scripts/extract_corpus.py` gains
  `--existing-corpus <path>`; rows merged by `source_file` +
  `row_id`/prompt hash — an unchanged source row inherits its
  fingerprint keys, a changed or dropped row does not inherit stale
  fingerprints. Fixture tests cover normal and `unknown` source ids.
- **Witnessed run record:** classifier model id, taxonomy version,
  date, classified/unfingerprinted counts (per failure reason), genre
  × sexual × gore distribution table, `other` audit status, and spend
  estimate vs. actual call count.

## Acceptance Criteria (revised per judgement, R-1…R-7)

- [ ] AC-01: A committed evidence artifact
  (`feature-requests/FR-890-evidence.md` + `scripts/fr890_evidence.py`)
  records the keyword scan command/results and 40 raw prompt row ids
  with concrete observations supporting the taxonomy. ✓ (this fold)
- [ ] AC-02: `data/corpus_fingerprint_taxonomy.yaml` defines
  `content.sexual`, `content.gore`, and `genre` labels, precedence,
  inclusion/exclusion rules, and fixture examples; FR-886 imports or
  references this artifact without redeclaring the taxonomy.
- [ ] AC-03: The classifier boundary accepts only `safe|mature` for the
  content axes and only the frozen 11-label genre enum; out-of-set
  output leaves the row unfingerprinted with a counted reason and is
  never coerced.
- [ ] AC-04: `other` is demoted behind every concrete genre before
  acceptance; if the witnessed run reports `other` > 10%, the run
  record includes 20 raw `other` samples and the corpus columns are
  not committed until the taxonomy artifact is revised and rerun.
- [ ] AC-05: Enrichment preserves prompt text, row order, and row count
  exactly; tests compare before/after row ids and prompt bytes.
- [ ] AC-06: Re-running enrichment skips rows already classified with
  the same taxonomy version and classifier model id, resumes
  unclassified rows, and records classified/unfingerprinted counts.
- [ ] AC-07: The live run has a preflight cost estimate and a tested
  stop-before-$10 guard keyed to attempted calls; no classifier retry
  is attempted for a failed row.
- [ ] AC-08: `scripts/extract_corpus.py` preserves fingerprint fields
  from an existing corpus by the merge key during re-extraction, with
  fixture coverage for normal and `unknown` source ids.
- [ ] AC-09: The enrichment run emits a genre × sexual × gore
  distribution report and stores run metadata reproducing the
  classifier model id, taxonomy version, date, row counts, and `other`
  audit status.
- [ ] AC-10: New REQ-DD requirements in a capability file (extend
  CAP-09 or new CAP) covering taxonomy validation, boundary rejection,
  additive writing, pass-through, resumability, cost stop, and
  distribution reporting; every new test carries
  `@pytest.mark.req(...)`.

## Constraints

- C-1: Spend ceiling $10 (operator-raised from $5, 2026-08-25); stop
  before exceeding.
- C-2: Haiku-class model only; classifier model id recorded per row.
- C-3: Columns additive only; no row mutation or reordering.
- C-4: This FR owns the taxonomy artifact; FR-886 imports it — no
  redeclaration (single source of truth). No FR-885 references.
- C-5: One LLM call per prompt, no retries — a failure is a counted
  unfingerprinted row (FR-886 already routes those conservatively).
- C-6: Junk-drawer cap on `other`: demote-last at the classifier
  boundary (most-specific-non-other instruction + precedence); if the
  witnessed run yields `other` > 10%, the run record must include 20
  sampled `other` prompts read raw, and the taxonomy is revised before
  the columns are committed — `other` must not eat correct answers.
- C-7 (judgement): full paid classifier run only after the taxonomy
  artifact, preflight cost estimate, and stop guard exist and are
  tested.

## Out of Scope

- Draw routing / eligibility join (FR-886).
- Model tolerance probing (FR-887/FR-888/FR-889 territory).
- Prompt rewriting or filtering — classification only.
- Multi-label genre or a style/medium axis (single dominant label
  suffices for the named consumers; revisit only with a named consumer
  for the second axis).
